**DHCPv6** — это ==сетевой протокол для автоматической настройки устройств в сетях [IPv6]==. Он раздает компьютерам и телефонам IP-адреса, адреса серверов DNS и другие важные параметры, работая похожим на старый добрый DHCP для IPv4 образом.

#### Отличия DHCPv4 и DHCPv6
- Не используется вложение в BOOT;
- Вместо широковещательной рассылки используется групповая:
	- FF02::1:2 - все DHCPv6 серверы и агенты;
	- FF05::1:3 - все DHCP - серверы предприятия (сайта);
- Используются UDP-порты 546 (клиент) и 547 (сервер).

#### Stateful и Stateless режим
- Stateful DHCPv6 - режим с сохранением состояния клиентов:
	- Сервер ведет базу выдаваемых адресов;
	- Вместе с адресом клиент получает необходимые настройки;
	- Сервер выбирает адрес, время аренды, и настройки для каждого клиента;
- Stateless DHCPv6 - режим без сохранения состояния клиентов:
	- Клиент подключается к серверу, уже имя действительный адрес;
	- Сервер отдает только дополнительные настройки, нужные для работы в сети.

#### Формат пакета DHCPv6 (базовый, клиент-сервер)

| Английское название                 | Русский перевод              | Размер (bit)                | Краткое описание                                                                                                                                                                                                                                                                                |
| ----------------------------------- | ---------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **msg-type** (Message Type)         | **Тип сообщения**            | 8                           | Тип DHCPv6-сообщения. Основные значения: `1` (SOLICIT), `2` (ADVERTISE), `3` (REQUEST), `4` (CONFIRM), `5` (RENEW), `6` (REBIND), `7` (REPLY), `8` (RELEASE), `9` (DECLINE), `10` (RECONFIGURE), `11` (INFORMATION-REQUEST), `12` (RELAY-FORW), `13` (RELAY-REPL).                              |
| **transaction-id** (Transaction ID) | **Идентификатор транзакции** | 24                          | Уникальный 3-байтовый идентификатор, генерируемый клиентом для сопоставления запросов и ответов. Сервер обязан вернуть тот же ID в ответе.                                                                                                                                                      |
| **options** (Options)               | **Опции**                    | переменная (кратна 8 битам) | Область опций, формат которой — `option-code` (2 байта), `option-len` (2 байта), `option-data` (переменная длина). Содержит все параметры конфигурации: DUID клиента и сервера, IA_NA (Identity Association for Non-temporary Addresses), IA_PD (Prefix Delegation), DNS-серверы, домены и т.д. |

#### Формат пакета DHCPv6 (ретранслятор, RELAY-FORW / RELAY-REPL)

| Английское название             | Русский перевод          | Размер (bit)                | Краткое описание                                                                                                                                                                                                        |
| ------------------------------- | ------------------------ | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **msg-type** (Message Type)     | **Тип сообщения**        | 8                           | Для ретранслятора всегда `12` (RELAY-FORW) или `13` (RELAY-REPL).                                                                                                                                                       |
| **hop-count** (Hop Count)       | **Счётчик переходов**    | 8                           | Количество ретрансляторов, через которые уже прошло сообщение. Увеличивается на 1 каждым ретранслятором. Если достигает порога (обычно 32), пакет отбрасывается.                                                        |
| **link-address** (Link Address) | **Адрес канала (линка)** | 128 (16 байт)               | IPv6-адрес, который сервер использует для определения интерфейса (канала), к которому подключён клиент. Обычно это адрес интерфейса ретранслятора, через который пришёл клиент.                                         |
| **peer-address** (Peer Address) | **Адрес узла (peer)**    | 128 (16 байт)               | IPv6-адрес клиента или предыдущего ретранслятора, от которого было получено оригинальное сообщение.                                                                                                                     |
| **options** (Options)           | **Опции**                | переменная (кратна 8 битам) | Обязательно содержит опцию `RELAY_MSG` (код 9), в которую инкапсулируется исходное сообщение клиента. Также могут присутствовать другие опции, например, `INTERFACE_ID` (код 18) для идентификации входного интерфейса. |

#### Принципиальные отличия от DHCPv4 (в табличной форме)

Если сравнить с вашей таблицей DHCPv4, ключевые различия выглядят так:

| Характеристика                | DHCPv4                                                            | DHCPv6                                                                                    |
| ----------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Размер базового заголовка** | 236 байт (фиксированный)                                          | 4 байта (всего два поля)                                                                  |
| **Идентификация клиента**     | MAC-адрес в поле `CHADDR` (16 байт)                               | DUID (в опциях, переменная длина)                                                         |
| **IP-адреса в заголовке**     | Есть поля `CIADDR`, `YIADDR`, `SIADDR`, `GIADDR` (все по 32 бита) | Нет полей для адресов в базовом заголовке; все адреса передаются в опциях (IA_NA / IA_PD) |
| **Magic Cookie**              | Есть (`0x63825363`) в начале опций                                | Отсутствует                                                                               |
| **Ретранслятор**              | Использует поле `GIADDR` (32 бита)                                | Имеет отдельный формат пакета с полями `link-address` и `peer-address` (оба по 128 бит)   |
| **Типы сообщений**            | 8 основных (DISCOVER, OFFER, REQUEST, ACK, NAK и др.)             | 13 типов, включая новые (SOLICIT, ADVERTISE, CONFIRM, RECONFIGURE и др.)                  |
| **Выделение адресов**         | Один IP-адрес на клиента                                          | Поддержка нескольких адресов (IA_NA) и делегирования префиксов (IA_PD)                    |
