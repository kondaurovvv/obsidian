**DHCP** (Dynamic Host Configuration Protocol) — это ==сетевой протокол, который автоматически назначает IP-адреса и другие параметры (маску подсети, шлюз) устройствам при подключении к сети, избавляя от необходимости настраивать их вручную==.

#### Настройка конечных узлов
- Для работы в IP-сети каждому узлу необходима предварительная настройка параметров:
	- IP-адрес и маска сети;
	- Адрес шлюза по умолчанию;
	- Адрес вспомогательных служб (DNS, WINS, TFTP,..);
	- Параметры стека IP (TTL, MTU,..);
	- Параметры работы систем в целом (загрузочный файл).
- Ручная настройка этих параметров возможно, но при большом количестве узлов резко вырастает вероятность ошибки.

#### Управление IP-адресами
- Ручное назначение IP-адресов имеет недостатки:
	- Новым системам необходимо выдавать новые, не использовавшиеся ранее адреса;
	- Более неиспользуемые адреса необходимо переназначать другим системам, но без системы учета адресов это делать тяжело;
	- Велика вероятность конфликтов.
- Использование системы учета адресов (IPAM) снижает вероятность ошибки или конфликтов, но обходится достаточно дорого.

#### Dynamic Host Configuration Protocol
- Является развитием (обратно совместим) с BOOTP:
	- Тот, в свою очередь, развился из протокола RARP.
- Основная задача - предоставление конечным узлам настроек, необходимых для работы сети;
- Может гибко управлять IP-адресами:
	- Выдавать узлам неиспользуемые адреса в аренду на фиксированный срок и помечать адреса как неиспользуемые, если аренда не продлена;
	- Выдавать узлам адреса по составленному списку;
	- Не гарантирует отсутствие конфликтов, но заметно снижает вероятность их возникновения.

#### Типы аренды адресов
- Сервер может выбрать IP-адрес для клиента одним из следующих методов:
	- Динамически - адрес выбирается из пула свободных адресов и при не продлении аренды возвращается в пул;
	- Вручную - клиенту сопоставляется постоянный адрес;
	- Автоматически - адреса для новых клиентов выбираются из пула, а затем сопоставляются на постоянной основе;
- Любые адреса выдаются в аренду, независимо от механизма выбора адреса сервером:
	- Аренда ограничена по времени;
	- Аренду необходимо продлять;
	- Клиент не знает механизм выбора адреса.

#### Взаимодействие узлов
- DHCP использует вложение в UDP:
	- Порт клиента - 67;
	- Порт сервера - 68.
- UDP вкладывается в IPv4, используемые адреса:
	- 0.0.0.0 - для клиента, желающего получить адрес;
	- 255.255.255.255 - для широковещательной рассылки.
- DHCP использует сообщения:
	- DHCPDISCOVER: обнаружение клиентом сервера/-ов;
	- DHCPOFFER: предложение сервером клиенту аренды;
	- DHCPREQUEST: запрос выбранного адреса:
	- DHCPACK: подтверждение аренды;
	- DHCPDECLINE: отказ от адреса при конфликте;
	- DHCPNAK: отказ сервера;
	- DHCPRELEASE: освобождение адреса;
	- DHCPFORCERENEW: принудительно обновить аренду;
	- DHCPINFORM: запрос дополнительных параметров без аренды.

#### Время аренды
- Любой адрес клиент трактует как временный;
- Срок аренды (Т) задает сервер (т.е. администратор);
- После окончания срока аренды клиент не имеет права продолжать использовать адрес;
- Можно продлить аренду, пока она действительна:
	- Первая попытка после половины срока (T1=T/2);
	- Следующие попытки - после половины оставшегося срока, но не позже T2 (обычно T2=7/8T);
	- После T2 - широковещательная попытка продления.
- Можно досрочно прекратить аренду:
	- Клиент - сообщением DHCPRELEASE;
	- Сервер - сообщениями DHCPFORCERENEW и DHCPNAK;

#### Формат пакета DHCP
![[Структура_DHCP_пакета.png]]

| Английское название                  | Русский перевод               | Размер (bit)                   | Краткое описание                                                                                                                |
| ------------------------------------ | ----------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **Op** (Operation Code)              | **Код операции**              | 8                              | Тип сообщения: `1` — запрос клиента (BOOTREQUEST), `2` — ответ сервера (BOOTREPLY).                                             |
| **HTYPE** (Hardware Type)            | **Тип оборудования**          | 8                              | Тип канального уровня. Для Ethernet равен `1`.                                                                                  |
| **HLEN** (Hardware Length)           | **Длина аппаратного адреса**  | 8                              | Размер MAC-адреса в байтах. Для Ethernet — `6`.                                                                                 |
| **HOPS** (Hops)                      | **Количество ретрансляторов** | 8                              | Количество DHCP-ретрансляторов (relay), через которые прошёл пакет. Клиент всегда ставит `0`.                                   |
| **XID** (Transaction ID)             | **Идентификатор транзакции**  | 32                             | Случайное число, выбранное клиентом для сопоставления запросов и ответов.                                                       |
| **SECS** (Seconds)                   | **Секунды**                   | 16                             | Количество секунд с начала процесса получения/обновления адреса.                                                                |
| **FLAGS** (Flags)                    | **Флаги**                     | 16                             | Управляющие биты. Старший бит (`Broadcast`) — если `1`, сервер отправляет ответ широковещательно.                               |
| **CIADDR** (Client IP Address)       | **IP-адрес клиента**          | 32                             | Текущий IP-адрес клиента, если он уже есть (в состояниях Bound/Renew).                                                          |
| **YIADDR** (Your IP Address)         | **Ваш IP-адрес**              | 32                             | IP-адрес, который сервер предлагает клиенту.                                                                                    |
| **SIADDR** (Server IP Address)       | **IP-адрес сервера**          | 32                             | IP-адрес следующего сервера (обычно DHCP-сервера).                                                                              |
| **GIADDR** (Gateway IP Address)      | **IP-адрес ретранслятора**    | 32                             | IP-адрес первого DHCP-ретранслятора. Если нет — `0`.                                                                            |
| **CHADDR** (Client Hardware Addr)    | **Аппаратный адрес клиента**  | 128 (16 байт)                  | MAC-адрес клиента (физический адрес).                                                                                           |
| **SNAME** (Server Hostname)          | **Имя сервера**               | 512 (64 байт)                  | Строка с именем DHCP-сервера (обычно не используется, заполняется нулями).                                                      |
| **FILE** (Boot Filename)             | **Имя загрузочного файла**    | 1024 (128 байт)                | Имя файла для загрузки (например, PXE). Обычно не используется.                                                                 |
| **OPTIONS** (Options / Magic Cookie) | **Опции**                     | переменная (от 0 до ~2496 бит) | Начинается с «магического числа» `0x63825363`, за которым следуют опции (тип, длина, значение). Завершаются опцией `255` (End). |
