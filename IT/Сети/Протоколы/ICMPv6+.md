**ICMPv6** (Internet Control Message Protocol for IPv6) — это ==важный служебный протокол сетевого уровня, созданный для работы с протоколом IPv6==. Он передает сообщения об ошибках, помогает проверять связь (например, в утилите ping) и заменяет сразу несколько старых протоколов из мира IPv4.

#### Internet Control Message Protocol v6
- Неотъемлемая часть протокола IPv6;
- Код вложения (Next Header) - 58:
	- Использует тот же формат заголовка, что и ICMP для IPv4;
	- Всегда последний заголовок, нет поля Next Header;
	- Контрольная сумма Internet Checksum считается от псевдозаголовка;
- Решает почти все сервисные задачи:
	- Типичные для ICMP задачи (оповещение об ошибках);
	- Обнаружение канальных адресов соседей (вместо ARP);
	- Базовая автонастройка конечных узлов (вместо DHCP);
	- Управление мультикастом (вместо IGMP).

|**Destination Unreachable**|**Пункт назначения недостижим**|**1**|**0-4**|Ошибка доставки (нет маршрута, запрещено админом, вне зоны действия, порт недоступен и др.).|
|**Packet Too Big**|**Пакет слишком велик**|**2**|**0**|Размер пакета превышает MTU следующего звена. Используется для Path MTU Discovery.|

|**Echo Request**|**Эхо-запрос**|**128**|**0**|Запрос на получение эхо-ответа (основа `ping6`).|
|**Echo Reply**|**Эхо-ответ**|**129**|**0**|Ответ на эхо-запрос (используется в `ping6`).|
|**Multicast Listener Query**|**Запрос слушателя многоадресной рассылки**|**130**|**0**|Запрос от маршрутизатора к узлам о том, какие многоадресные группы они слушают (MLDv1/v2).|
|**Multicast Listener Report**|**Отчет слушателя многоадресной рассылки**|**131**|**0**|Ответ узла о том, что он присоединился к группе (MLDv1).|
|**Multicast Listener Done**|**Завершение слушателя многоадресной рассылки**|**132**|**0**|Уведомление о выходе из многоадресной группы (MLDv1).|
|**Router Solicitation**|**Запрос маршрутизатора**|**133**|**0**|Узел запрашивает у маршрутизаторов информацию для автоконфигурации.|
|**Router Advertisement**|**Объявление маршрутизатора**|**134**|**0**|Маршрутизатор отвечает на Solicitation или периодически рассылает свои параметры.|

|**Redirect Message**|**Перенаправление**|**137**|**0**|Маршрутизатор сообщает узлу, что для данного получателя лучше использовать другой маршрутизатор.|
|**Router Renumbering**|**Перенумерация маршрутизатора**|**138**|**0-1**|Используется для обновления номеров префиксов на маршрутизаторах (устаревающий протокол).|
|**ICMP Node Information Query**|**Информационный запрос узла**|**139**|**0-3**|Запрос информации об узле (имя хоста, IPv6-адрес, и т.д.).|
|**ICMP Node Information Response**|**Информационный ответ узла**|**140**|**0-3**|Ответ на информационный запрос.|
|**Inverse Neighbor Discovery Solicitation**|**Запрос обратного обнаружения соседа**|**141**|**0**|Запрос IPv6-адреса по известному MAC-адресу.|
|**Inverse Neighbor Discovery Advertisement**|**Объявление обратного обнаружения соседа**|**142**|**0**|Ответ на запрос обратного обнаружения.|
|**Multicast Listener Report (v2)**|**Отчет слушателя многоадресной рассылки v2**|**143**|**0**|Более гибкий отчет о членстве в группах (MLDv2).|
|**Home Agent Address Discovery Request**|**Запрос обнаружения домашнего агента**|**144**|**0**|Запрос мобильного узла для обнаружения домашнего агента (Mobile IPv6).|
|**Home Agent Address Discovery Reply**|**Ответ обнаружения домашнего агента**|**145**|**0**|Ответ с адресом домашнего агента.|
|**Mobile Prefix Solicitation**|**Запрос мобильного префикса**|**146**|**0**|Запрос обновления префиксов для мобильного узла.|
|**Mobile Prefix Advertisement**|**Объявление мобильного префикса**|**147**|**0**|Ответ с новыми префиксами для мобильного узла.|
|**Certification Path Solicitation**|**Запрос пути сертификации**|**148**|**0**|Запрос на проверку сертификатов (SEND - Secure Neighbor Discovery).|
|**Certification Path Advertisement**|**Объявление пути сертификации**|**149**|**0**|Предоставление пути сертификации для проверки (SEND).|
|**ICMP messages utilized by experimental mobility protocols**|**Сообщения для экспериментальных протоколов мобильности**|**150**|**0**|Зарезервировано для экспериментов с мобильностью.|
|**Multicast Router Advertisement**|**Объявление многоадресного маршрутизатора**|**151**|**0**|Используется протоколом Multicast Routing.|
|**Multicast Router Solicitation**|**Запрос многоадресного маршрутизатора**|**152**|**0**|Используется протоколом Multicast Routing.|
|**Multicast Router Termination**|**Завершение работы многоадресного маршрутизатора**|**153**|**0**|Используется протоколом Multicast Routing.|
|**FMIPv6 Messages**|**Сообщения FMIPv6**|**154**|**0-3**|Используются в протоколе быстрого переключения для мобильных узлов (Fast Handover).|
|**RPL Control Message**|**Управляющее сообщение RPL**|**155**|**0-3**|Используется в протоколе маршрутизации RPL для сетей с низким энергопотреблением (IoT).|
|**ILNPv6 Locator Update Message**|**Сообщение обновления локатора ILNPv6**|**156**|**0-1**|Используется в протоколе Identifier-Locator Network Protocol.|
|**Duplicate Address Request**|**Запрос дублирующего адреса**|**157**|**0**|Запрос для проверки дублирования адреса (DAD).|
|**Duplicate Address Confirmation**|**Подтверждение дублирующего адреса**|**158**|**0**|Подтверждение результата проверки DAD.|
|**MPL Control Message**|**Управляющее сообщение MPL**|**159**|**0-1**|Используется в Multicast Protocol for Low-Power and Lossy Networks.|
|**Extended Echo Request**|**Расширенный эхо-запрос**|**160**|**0**|Запрос расширенной диагностики с указанием целевого интерфейса.|
|**Extended Echo Reply**|**Расширенный эхо-ответ**|**161**|**0**|Ответ с расширенной диагностической информацией.|

#### SNNA
- Solicited-node multicast address;
- Группа узлов с адресами, заканчивающимися на заданные 24 бита:
	- Последние 24 бита адреса добавляются к префиксу ff02::1:ff28:9c5a;
	- Например, адресу fe80::2aa:ff:fe==28:9c5a== соответствует SNMA ff02::1:ff==28:9c5a==;
	- Почти всегда узел будет единственным участником в группе SNMA;
- В канальных средах с мультикастом имеет предсказуемый адрес:
	- Например, в Ethernet
