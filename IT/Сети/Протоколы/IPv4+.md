
 - 1980 RFC 760, стандартизация IPv4;
 - Размер - 32 бита;
 - Назначается на канальный интерфейс;
 - Должен быть уникальным в пределах всей сети;
 - Состоит из двух частей;
	 - Идентификатор канальной сети (Network ID);
		 - обязан совпадать у всех хостов в одном канале;
		 - обязан различаться у хостов в разных каналах;
		 - назначается администратором IP-сети.
	 - Идентификатор хоста в канале (Host ID).
		 - назначается администратором канальной среды;
 - Удобно записывать адреса в виде 4 октетов (чисел от 0 до 255), разделенных точками "127.0.0.1" (или 2130706433 это тоже IPv4 адрес);
 - Функция inet_aton() в стеке BSD поддерживает особые форматы записи классовых адресов:
	 - Класс A: 8bit.24bit (например, 127.1 или 10.657921);
	 - Класс B: 8bit.8bit.16bit (например, 127.16.1).
 - На одном устройстве может быть много канальных интерфейсов, и на каждом из них может быть назначен (или не назначен) IP-адрес:
	 - В каждую канальную среду на IP-устройстве должен смотреть максимум один канальный интерфейс;
	 - Как следствие - адреса на разных интерфейсах должны быть из разных сетей.
 - На интерфейсе может быть несколько IP-адресов:
	 - Один из них основной, остальные - вторичные;
	 - Адреса на одном интерфейсе могут быть из одной сети.

#### Формат заголовка IPv4
- Заголовок IPv4-пакета:
	- Приведены актуальное названия полей, ранее некоторые из них назывались иначе;
	- Никаких других полей в заголовке IPv4 НЕТ!

#### Формат пакета IPv4
![[Структура_IPv4_пакета.png|900]]

| Английское название        | Русский перевод                                                       | Размер bit                | Краткое описание                                                                                             |
| -------------------------- | --------------------------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Version**                | **Версия**                                                            | 4                         | Номер версии IP-протокола (для IPv4 всегда равно 4).                                                         |
| **Header Length**          | **Длина заголовка**                                                   | 4                         | Длина заголовка в 32-битных словах. Минимум 5 (20 байт).                                                     |
| **DSCP**                   | **Код дифференцированных услуг** (Differentiated Services Code Point) | 6                         | Используется для задания приоритета и класса обслуживания (QoS).                                             |
| **ECN**                    | **Явное уведомление о перегрузке** (Explicit Congestion Notification) | 2                         | Позволяет маршрутизаторам сообщать о перегрузке, не отбрасывая пакеты.                                       |
| **Total Length**           | **Общая длина**                                                       | 16                        | Общий размер всего IP-пакета (заголовок + данные) в байтах.                                                  |
| **Identification**         | **Идентификатор**                                                     | 16                        | Уникальный номер пакета, используется для сборки фрагментированных пакетов.                                  |
| **Flags**                  | **Флаги**                                                             | 3                         | Управляющие флаги: бит 0 (зарезервирован), бит 1 (DF – не фрагментировать), бит 2 (MF – есть ещё фрагменты). |
| **Fragment Offset**        | **Смещение фрагмента**                                                | 13                        | Указывает положение фрагмента относительно начала исходного пакета (в единицах по 8 байт).                   |
| **Time to live**           | **Время жизни**                                                       | 8                         | Максимальное число маршрутизаторов (hop'ов), которое пакет может пройти. Уменьшается на каждом переходе.     |
| **Protocol**               | **Протокол**                                                          | 8                         | Определяет протокол следующего уровня (например, TCP = 6, UDP = 17, ICMP = 1).                               |
| **Header Checksum**        | **Контрольная сумма заголовка**                                       | 16                        | Проверочная сумма, вычисляемая только для заголовка (данные не проверяются).                                 |
| **Source IP Address**      | **IP-адрес отправителя**                                              | 32                        | Адрес узла, отправившего пакет.                                                                              |
| **Destination IP Address** | **IP-адрес получателя**                                               | 32                        | Адрес узла, которому предназначен пакет.                                                                     |
| **OPTIONS**                | **Опции**                                                             | _переменный (до 40 байт)_ | Дополнительные поля, необязательные. Используются редко (для маршрутизации, таймштампов и т.п.).             |
| **DATA**                   | **Данные**                                                            | _переменный_              | Полезная нагрузка (передаваемая информация) протоколов более высокого уровня.                                |

- Как правило, канальные среды не пропускают слишком большие кадры:
	- Максимальный размер вложения в стандартный Ethernet - 1500 байт.
- Если размер отправляемого через интерфейс IP-пакета превышает MTU этого интерфейса, есть два возможных действия:
	- Не отправлять пакет вовсе;
	- Разрезать данные из пакета на части подходящего размера и отправить фрагменты в отдельных пакетах.



#### В IPv4 используются три основных типа адресации и передачи данных:
- Unicast (одноадресная рассылка)
- Broadcast (широковещательная рассылка)
- Multicast (многоадресная рассылка)

### Ключевые выводы
- Минимальный заголовок IPv4 — 20 байт (5 машинных слов); поле Options на практике не используется, и 100% современных пакетов имеют заголовок ровно 20 байт;
- TTL фактически является счётчиком прыжков: каждый маршрутизатор вычитает единицу, при достижении нуля пакет уничтожается — это защита от петель маршрутизации;
- Фрагментация — процессорно-затратная операция, которую следует избегать; механизм Path MTU Discovery с флагом DF позволяет определить максимальный размер пакета на всём маршруте;
- Header Checksum защищает только от случайных ошибок передачи, но не от умышленной модификации — это не цифровая подпись;
- Статус historic по RFC 2026 означает прекращение разработки новых стандартов для IPv4 и переходных технологий — существующие механизмы заморозятся;
- IPv4 будет использоваться ещё минимум 20 лет, но развиваться не будет — все возможности протокола исчерпаны вместе с адресным пространством;
- 4G/LTE уже работает на IPv6 нативно; если вы пользуетесь мобильным интернетом, вы используете IPv6 прямо сейчас;
- IoT и Internet of Everything требуют адресов в масштабах, принципиально недостижимых для 32-битного пространства IPv4.
