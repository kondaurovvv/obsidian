**ICMPv6** (Internet Control Message Protocol for IPv6) — это ==важный служебный протокол сетевого уровня, созданный для работы с протоколом IPv6==. Он передает сообщения об ошибках, помогает проверять связь (например, в утилите ping) и заменяет сразу несколько старых протоколов из мира IPv4.

#### Internet Control Message Protocol v6
- Неотъемлемая часть протокола IPv6;
- Код вложения (Next Header) - 58:
	- Использует тот же формат заголовка, что и ICMP для IPv4;
	- Всегда последний заголовок, нет поля Next Header;
	- Контрольная сумма Internet Checksum считается от псевдозаголовка;
- Решает почти все сервисные задачи:
	- Типичные для ICMP задачи (оповещение об ошибках);
	- Обнаружение канальных адресов соседей (вместо ARP);
	- Базовая автонастройка конечных узлов (вместо DHCP);
	- Управление мультикастом (вместо IGMP).

#### SNNA
- Solicited-node multicast address;
- Группа узлов с адресами, заканчивающимися на заданные 24 бита:
	- Последние 24 бита адреса добавляются к префиксу ff02::1:ff28:9c5a;
	- Например, адресу fe80::2aa:ff:fe==28:9c5a== соответствует SNMA ff02::1:ff==28:9c5a==;
	- Почти всегда узел будет единственным участником в группе SNMA;
- В канальных средах с мультикастом имеет предсказуемый адрес:
	- Например, в Ethernet ff02::1:ff==28:9c5a== будет иметь MAC 33:33:ff:==28:9c:5a==.

#### Neighbor Solicitation/Advertisement
- Механизм разрешает известный адрес IPv6 в неизвестный канальный:
	- Запрашивающий узел отсылает NS на SNMA запрашиваемого адреса;
	- Обладатель адреса отвечает NA со своим канальным адресом.
- Duplicate Address Detection (DAD) проверяет конфликты адресов.

#### NUD
- Neighbor Unreachability Detection (NUD) - механизм обнаружения недоступности узла в процессе коммуникации с этим узлом;
- Поведение при обнаружении отказа зависит от места отказа:
	- Если недоступен получатель в общем канале - повторно выполняется ND;
	- Если недоступен транзитный маршрутизатор - переключается маршрут.
- Обнаружение отказа зависит от протокола коммуникации.
	- Если из коммуникации очевидно, что получатель доступен или недоступен (как в TCP) - используются данные протокола коммуникации.
	- Если протокол коммуникации не предоставляет данные о доступности - узел периодически проверяет next hop сообщениями Neighbor Solicitation.

#### Таблица кэша Neighbor Discovery
- Принцип кэширования аналогичен оному в ARP;
- Записи в кэш имеются состояния:

| Состояние                          | Что это значит?                                                                                         | Как ведет себя система?                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 🔴 **INCOMPLETE** _(Не завершено)_ | • Адрес соседа уже известен.  <br>• Физический **MAC-адрес еще не найден**.                             | Прямо сейчас идет активная **отправка запросов** (Neighbor Solicitation) для поиска MAC-адреса.             |
| 🟢 **REACHABLE** _(Доступен)_      | • Сосед точно находится в сети.  <br>• Связь проверена совсем недавно.                                  | Пакеты данных **успешно ходят** в обе стороны. Проверка связи не требуется.                                 |
| 🟡 **STALE** _(Устарело)_          | • MAC-адрес соседа все еще сохранен в памяти.  <br>• Прошло слишком много времени с последней проверки. | Новые данные на этот адрес **пока не отправлялись**. Система не проверяет связь, пока нет трафика.          |
| 🔵 **DELAY** _(Ожидание)_          | • На старый адрес (из состояния STALE) ушли новые данные.                                               | Система **ждет несколько секунд** подтверждения от соседа. Запросы на проверку сети пока не отправляются.   |
| 🟤 **PROBE** _(Проверка)_          | • Подтверждение в режиме DELAY так и не пришло.                                                         | Система отправляет **точечные запросы** для проверки связи. Если ответа не будет, соседа удалят из таблицы. |

#### Router Solicitation/Advertisement
- Маршрутизатор рассылают по расписанию RA с указанием используемых в канале параметров IPv6;
- Узлы могут запросить внеплановую рассылку RA с помощью RS.

#### Prefix information и Stateless Address Autoconfiguration
- RA использует опцию Prefix information для указания доступных сетей:
	- Type 3, Lenght 4 (32 байта);
	- Preferred/Valid Lifetime задается в секундах, Prefix Length - от 0 до 128;
	- L (on-link): можно ли трактовать как on-link другие адреса в этой сети;
	- A (autonomous address-configuration): префикс можно использовать для SLAAC.
- Получившие RA с PI узлы генерируют действительный адрес в сети.
