#### Зачем нужен DNS?
- Система DNS позволяет преобразовать имена в компьютеров в IP-адрес.
	- www.yandex.ru -> 77.88.55.66;
- Преимущества DNS:
	- Понятные человеку имена;
	- возможность менять сетевую инфраструктуру.

#### Утилита nslookup
- nslookup yandex.ru;
- Другие утилиты (Linux):
	- host;
	- dig.

**Пример**
Сервер:  dc1.imm.uroran.ru
Address:  192.168.15.1

Не заслуживающий доверия ответ:
		yandex.ru
Addresses:  2a02:6b8:a::a
          5.255.255.77
          77.88.55.88
          77.88.44.55

#### Файл /etc/hosts
- Файл содержит имена компьютеров их адреса;
	- Linux/Unix: /etc/hosts;
	- Windows: С:\Windows\System32\drivers\etc\hosts
- **Пример**:
	- 102.54.94.97   server;
	- 38.25.63.10   my-client.
- Недостатки:
	- Быстро увеличивается размер;
	- Сложность вносить изменения;
	- Возможны конфликты имен.

#### Особенности DNS
- Распределённая система:
	- Нет единого сервера, на котором описываются имена хостов;
- Делегирование ответственности:
	- Пространство имен разделено на отдельные части - домены;
	- За каждый домен отвечает отдельная организация.
- Надежность:
	- Дублирование серверов DNS.

#### Структура доменного имени
- **Пример**:
	- ==www== . ==urfu== . ==ru== :
		- ==ru== - Домен верхнего уровня;
		- ==urfu== - Домен второго уровня;
		- ==www== - Имя компьютера.

#### Распределение доменных имен
- Распределением доменных имен занимаются регистраторы;
- Регистратор корневого домена один:
	- Internet Corporation for Assigned Names and Numbers (ICAN).
- Регистраторы зон первого уровня:
	- Необходима аккредитация в ICANN;
	- Один или несколько регистраторов для каждой зоны;
	- Регистрируют домены второго уровня.

#### Режимы работы DNS
- Итеративный:
	- Если сервер отвечает за данную доменную зону - он возвращает ответ:
	- Если не отвечает, то возвращает адрес DNS-сервера, у которого есть более точная информация.
- Рекурсивный:
	- Сервер сам выполняет запросы к другим серверам DNS, чтобы найти нужный адрес.

#### Сервер разрешения имен DNS (DNS Resolver)
- Предоставляется провайдером/организацией:
	- Компьютер получает адрес локального сервера DNS по DHCP.
- Открытый сервер:
	- Google: 8.8.8.8 и 8.8.4.4;
	- Яндекс 77.88.8.8 и 77.88.8.7 (с блокировкой порно и эротики).

#### Типы ответов DNS
- Авторитетный (authoritative, "заслуживающий доверия"):
	- Ответ от сервера, обслуживающего доменную зону;
	- Получен из файлов на диске сервера.
- Неавторитетный (non-authoritative, "не заслуживающий доверия"):
	- Ответ от сервера, который не обслуживает доменную зону;
	- Получен из кэша, данные могли устареть.

#### Протокол DNS
- Модель клиент-сервер;
- Запрос-ответ;
- DNS использует протокол UDP;
	- Номер порта 53.

#### 1. Заголовок DNS (DNS Header) — фиксированные 96 бит (12 байт)
|Английское название|Русский перевод|Размер (bit)|Краткое описание|
|---|---|---|---|
|**Transaction ID (ID)**|**Идентификатор транзакции**|16|Сопоставляет запрос и ответ. Клиент генерирует число, сервер повторяет его в ответе.|
|**QR (Query/Response)**|**Флаг запроса/ответа**|1|Определяет тип сообщения: `0` — запрос, `1` — ответ.|
|**OPCODE**|**Код операции**|4|Тип запроса: `0` — стандартный, `1` — обратный, `2` — статус сервера.|
|**AA (Authoritative Answer)**|**Авторитетный ответ**|1|Указывает, что сервер является авторитетным для данной зоны (`1` — да).|
|**TC (Truncation)**|**Усечение**|1|Указывает, что пакет был обрезан (из-за превышения лимита UDP, обычно 512 байт).|
|**RD (Recursion Desired)**|**Желание рекурсии**|1|Клиент запрашивает у сервера рекурсивный режим работы (`1` — да).|
|**RA (Recursion Available)**|**Доступность рекурсии**|1|Сервер сообщает, поддерживает ли он рекурсивные запросы (`1` — да).|
|**Z (Reserved)**|**Зарезервировано**|3|Зарезервированное поле. Должно быть равно `0`.|
|**RCODE (Response Code)**|**Код ответа**|4|Статус ответа: `0` — ошибок нет, `3` — домен не найден (NXDomain) и др.|
|**QDCOUNT**|**Количество вопросов**|16|Количество записей в секции вопроса (обычно равно `1`).|
|**ANCOUNT**|**Количество ответов**|16|Количество записей в секции ответов (Resource Records).|
|**NSCOUNT**|**Количество авторитетных записей**|16|Количество записей в секции полномочий (Authority).|
|**ARCOUNT**|**Количество дополнительных записей**|16|Количество записей в дополнительной секции (Additional).|
#### 2. Секция вопроса (Question Section) — переменная длина

| Английское название | Русский перевод               | Размер (bit)          | Краткое описание                                                                                                |
| ------------------- | ----------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------- |
| **QNAME**           | **Имя запрашиваемого домена** | Переменная (до ~2048) | Доменное имя в виде последовательности меток (каждая метка: 1 байт длины + данные, завершается нулевым байтом). |
| **QTYPE**           | **Тип запроса**               | 16                    | Тип искомой записи. Например: `1` (A), `28` (AAAA), `15` (MX), `2` (NS).                                        |
| **QCLASS**          | **Класс запроса**             | 16                    | Класс сети. Для Интернета почти всегда равен `1` (IN).                                                          |
#### 3. Формат ресурсной записи (Resource Record) — используется в секциях Answer, Authority и Additional

Каждая запись в этих секциях имеет одинаковую структуру. Количество записей задаётся счетчиками `ANCOUNT`, `NSCOUNT` и `ARCOUNT` из заголовка.

|Английское название|Русский перевод|Размер (bit)|Краткое описание|
|---|---|---|---|
|**NAME**|**Имя домена**|Переменная|Доменное имя, к которому относится данная запись (может быть сжато).|
|**TYPE**|**Тип записи**|16|Тип данных (A, AAAA, CNAME, MX, TXT и т.д.).|
|**CLASS**|**Класс записи**|16|Класс протокола (обычно `1` для IN).|
|**TTL (Time To Live)**|**Время жизни**|32|Время в секундах, в течение которого запись можно кэшировать.|
|**RDLENGTH**|**Длина данных**|16|Длина поля `RDATA` в байтах.|
|**RDATA**|**Данные записи**|Переменная (зависит от RDLENGTH)|Непосредственно данные: IP-адрес (для A/AAAA), имя сервера (для CNAME/NS), приоритет и хост (для MX) и т.д.|

#### Типы записей DNS
- Каждая DNS запись (Resource Record, RR) имеет:
	- Тип записи - для чего предназначена запись;
	- Класс записи - в каких сетях используется (IN - Интернет)
- Типы записей для IP-адресов:
	- A - IPv4 адрес компьютер;
	- AAAA - IPv6 адрес компьтера.

#### DNS псевдонимы
- Запись типа CNAME (Canonical Name Record/каноническая запись имени):
	- Определяет псевдоним для другого доменного имени;
	- ftp.asozykin.ru -> www.asozykin.ru
- Альтернативный способ:
	- Задать несколько A записей для одного IP-адреса.

#### Адреса почтового сервера
- Нужно отправить почту на адрес networks@gmail.com:
- Запись типа MX (Mail eXchange):
	- 5 gmail-smtp-in.l.google.com;
	- 10 alt1.gmail.smtp-in.l.google.com
	- 20 alt2.gmail.smtp-in.l.google.com
	- 30 alt3.gmail.smtp-in.l.google.com
	- 40 alt4.gmail.smtp-in.l.google.com

#### Адреса сетевых сервисов
- Для некоторых сервисов можно задавать не только IP-адреса, но и порты:
	- Jabber;
	- CIP;
	- Kerberos.
- Запись типа SRV(Service record):
	- _сервис._протокол.имя. -> приоритет вес порт имя;
	- _xmpp-server._tcp.example.com. -> 0 5 5269 xmpp.example.com;
	- _xmpp-server._tcp.example.com. -> 20 0 5269 backup_xmpp.example.com;

#### Запись серверов имен
- Запись типа NS (Name Server):
	- Указывает адрес DNS-серверов, отвечающих за зону.
**Пример:**
- yandex.ru  ->ns1.yandex.ru , ns1.yandex.ru;
- urfu.ru -> ns1.urfu.ru , ns2.urfu.ru , ns3.urfu.ru.

- Вышестоящий домен использует "приклеенные" A-записи, чтобы определить адреса сервисов в NS-записях.
