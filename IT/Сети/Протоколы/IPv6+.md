 - 1998 RFC 2460, стандартизация IPv6;

#### Задачи IPv6
- Вернуть в протокол IP изначально задуманные преимущества:
	- Связность "от края до края";
	- Предсказуемость классовой адресации (при сохранении преимуществ CIDR);
	- Расширяемая функциональность заголовка.
- Оптимизировать протокол IP под реальность XXI века:
	- Избавиться от необходимости использовать сторонние протоколы;
	- Обеспечить достаточно большое количество адресов;
	- Упростить заголовок для ускорения и облегчения маршрутизации;
	- Реализовать стандартные механизмы безопасности, QoS, мобильности.

#### Сравнение IPv4 IPv6
#### IPv4                     
- **4 294 967 296** адресов мало;
	- Необходимость NAT;
	- Коллизии между частными и публичными адресами;
- Классовая маршрутизация - родовая травма;
- Неоптимальный заголовок;
- Много служебных протоколов;
- Сложность настройки узлов;
- Отсутствие доп. расширений;
	- В частности, механизмов обеспечения безопасности;
- Минимальный MTU - 576 байт.

#### IPv6
- **340 282 366 920 938 463 463 746 074 317 682 11 456** адресов;
	- Связь "от края до края";
	- Единое пространство адресов.
- Оптимизация заголовка и процедуры маршрутизации;
	- Фрагментация на отправителе;
	- Отсутствие широковещания.
- Единый служебный протокол;
	- Штатный механизм автоконфигурации узлов.
- Механизм расширений;
	- Обязательная поддержка Ipsec.
- Минимальный MTU - 1280 байт.

#### Типы взаимодействия в IPv6
- Unicast: одноадресное передача единственному адресату:
	- Основной тип взаимодействия в Интернете.
- Multicast: многоадресная передача группе адресатов:
	- Экономит полосу при отправке группе адресатов, не требует unicast-адресов.
- Anycast: альтернативная передача единственному адресату из группы
	- Используется для уменьшения времени реакции (например, в службе DNS).
![[Типы_взаимодействия_в_IPv6.jpg|900]]
==**Широковещательная рассылка (broadcast) в IPv6 отсутствует.**==

#### Особенности Unicast-адресации в IPv6
- Адрес назначается на интерфейс узла IPv6:
	- На одном узле может быть несколько интерфейсов;
	- На одном интерфейсе может быть несколько адресов.
- Адреса должны быть уникальными в пределах всей сети (Интернет):
	- Исключение - некоторые не маршрутизируемые адреса (в т. ч. LLA).

#### Адреса IPv6
- Размер адреса IPv6 - 128 бит:
	- Записывается в шестнадцатеричном виде:
		- 8 групп по 4 разряда, разделенных двоеточиями.
**Пример**
==2001:0DB8:B16B:00B5:0000:0000:0000:0001==

- Активно используется сокращенный формат записи:
	- Старшие нуди в каждом октете можно опустить, если октет не нулевой;
	- Не более чем в одном месте адреса нескольких нулевых октетов подряд можно заменить двумя двоеточиями.
**Пример**
==2001:DB8:B16B:B5::1==

- Сокращенная запись однозначно соответствует полной.

#### Маска адреса
- Как и в IPv4, адреса делятся на две части:
	- Network ID - общий для всех узлов в канале;
	- Interface ID - идентификатор узла в канале.
	- Для нахождения границы между Network ID и Interface ID используется маска.
- Формат записи маски - только префиксный:
	- 2001:DB8::/32 - сеть, все узлы которой имеют адреса, начинающиеся на 32 бита 
	  0010 0000 0000 0001 000 1101 1011 1000 (0x20010DB8);
	- ::1/128 - сеть, содержащая единственный адрес ::1.
- В большинстве случаев на конечные узлы назначается сеть /64:
	- На каналах точка-точка допустимо использовать /127;
	- При желании разрешается использовать и другие маски.

#### Типы адресов IPv6
- Global Unicast (2000::/3);
- Unique Local Unicast (fc00::/7);
- Link Local Unicast (fe80::/10);
- Multicast (ff00::/8);
- Специальные адреса (::ffff:0:0/96, ::1/128, ::/128,...).

#### Global Unicast
- Адреса, маршрутизируемые в Интернете:
	- Аналог "публичных" адресов в IPv4;
- Входят в блок 2000::/3:
	- Начинаются на 001<sub>2</sub>, т. е. на 2<sub>16</sub> = 0010<sub>2</sub> или 2<sub>16</sub> = 0011<sub>2</sub>;
- DВыстроены в иерархию:
	- RIR получают блоки /23 (или крупнее, вплоть до /12)

#### В IPv6 используются три основных типа адресации и передачи данных:
- Unicast (одноадресная адресация);
- Anycast (эникастная адресация);
- Multicast (групповая адресация);

| ----------------------- | --------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Version**             | **Версия**                  | 4                       | Номер версии IP-протокола. Для IPv6 всегда равен 6.                                                                                                                                         |
| **Traffic Class**       | **Класс трафика**           | 8                       | Используется для управления качеством обслуживания (QoS) и приоритезации (аналог DSCP/ECN в IPv4).                                                                                          |

#### Hop-by-Hop Options и Destination Options
- Опции, адресованные конкретным участникам взаимодействия:
	- Hop-by-Hop Options: для всех узлов;
	- Destination Options: для принимающего узла.
- Задают одну или несколько TVL-опций:
	- Старшие два бита типа указывают на поведение для незнакомых опций;
	- Третий по старшинству бит указывает на возможность изменения опции;
	- Опции типов 0 (Pad1) и 1 (PadN) используются для выравнивания.

#### Fragment Header
- Фрагментация в IPv6 выполняется только узлом-отправителем:
	- Если транзитный маршрутизатор не может отправить пакет в среду с малым MTU, он сбрасывает пакет и отправляет ICMP-сообщение Packet Too Big.
- Поля Fragment Offset, More Fragments и Identification сохранили роли:
	- Identification (32 бита) - уникальный "за последнее время" идентификатор;
	- More Fragments (1 бит) означает, что фрагмент не последний;
	- Fragment Offset (13 бит) задает смещение относительно начала фрагментируемой части пакета, заданное в 8-байтовых блоках.
- Фрагментируемая часть начинается после заголовков Routing Header (если есть), Hop-by-Hop Option (если есть) или после основного. 

#### Ключевые выводы
- Адресное пространство IPv4 полностью исчерпано: у IANA нет свободных блоков /8 с 2011 года, региональные регистраторы работают в режиме жёсткой экономии;
- NAT — не средство безопасности, а костыль для экономии адресов; в IPv6 его заменяет огромное адресное пространство (3,4 * 10^38 адресов) и сквозная связность;
- IPv6 убирает broadcast полностью, заменяя его multicast, что устраняет паразитную нагрузку на все узлы в сегменте;
- IPsec в IPv6 обязателен: любой узел гарантированно способен согласовать защищённое соединение;
- Фрагментация в IPv6 выполняется только отправителем, а минимальный MTU увеличен с 576 до 1280 байт;
-  В IPv6 на одном интерфейсе нормально иметь несколько адресов разных типов (link-local + global unicast + unique local), и протокол автоматически выбирает нужный адрес источника;
- Unique local адреса (fd00::/8) не выходят в интернет и не NATятся — для доступа наружу нужен отдельный global unicast адрес на том же интерфейсе;
- Modified EUI-64 легко опознать по токену FF:FE на границе 6-й и 7-й групп адреса; он вычисляется из MAC-адреса с инверсией 7-го бита;
- Subnet-router anycast (Interface ID = все нули) позволяет нескольким маршрутизаторам обслуживать один адрес, обеспечивая штатную отказоустойчивость;
- Адреса имеют конечное время жизни: preferred lifetime определяет период активного использования, valid lifetime — момент полного удаления;
- Flow Label (20 бит) задаётся отправителем и не меняется при транзите — это позволяет балансировать зашифрованный IPsec-трафик без reordering, даже когда транспортные заголовки скрыты;
- Payload Length считает размер данных без фиксированного заголовка, в отличие от Total Length в IPv4, что даёт до 65 535 байт полезной нагрузки;
- Дополнительные заголовки имеют строгий порядок: Hop-by-Hop всегда первый, Routing — второй, остальные произвольно;
- Fragment Header использует 32-битный Identification вместо 16-битного в IPv4, решая проблему перемешивания фрагментов на высокоскоростных каналах;
- Нефрагментируемая часть пакета (фиксированный заголовок + Hop-by-Hop + Routing) дублируется в каждом фрагменте для корректной транзитной обработки;
