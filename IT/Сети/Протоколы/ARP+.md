**ARP** (Address Resolution Protocol или протокол разрешения адресов) — это ==сетевой протокол, который нужен для того, чтобы узнать физический **MAC-адрес** устройства в локальной сети по его известному логическому **IP-адресу**==.

- Альтернативное название RFC: Converting Network Protocol Addresses to 48.bit Ethernet Address for Transmission on Ethernet Hardware;
- Может работать с любым протоколом, использующим MAC-адреса и поддерживающим широковещательную рассылку.

#### Принцип работы ARP
- В какой ситуации необходим ARP:
	- "Отправителю" требуется отправить узлу, находящемуся с ним в одной среде Ethernet ("получателю"), IP-пакет;
	- IP-адрес получателя известен;
	- Mac-адрес получателя неизвестен.
- ARP запрашивает MAC получателя, указывая его IP:
	- Запрос идет в широковещательном кадре;
	- "Получатель" видит свой IP-адрес в запросе и отпраdляет в ответ кадр со своими IP и MAC-адресом;
	- "Отправитель", зная MAC, отправляет оригинальный пакет.

**Кэш ARP**
- Отправлять запрос ARP на каждый пакет накладно;
- IP-адреса и MAC-адреса у узлов меняются редко;
- Разумно в течение некоторого времени хранить известные пары IP+MAC в промежуточной таблице:
	- Пополнять таблицу автоматически при получении любого ARP-пакета (он содержит IP и MAC отправителя);
	- Но не хранить привязки вечно, они должны устаревать;
- Если запись в таблице -пакет отправляется, если нет - откладывается в буфер или удаляется.

**Формат пакета ARP**
- В случае IP+Ethernet:
	- Инкапсуляция: ARPA, Ethertype: 0x0806;
	- HTYPE: 0x0001, PTYPE: 0x0800;
	- HLEN: 0x06, PLEN: 0x04;
	- OPER:
		- 0x0001 для запроса
		- 0x0002 для ответа

| Английское название                | Русский перевод                  | Размер bit | Краткое описание                                                                   |
| ---------------------------------- | -------------------------------- | ---------- | ---------------------------------------------------------------------------------- |
| **Hardware Type (HTYPE)**          | **Тип оборудования**             | 16         | Тип сетевого протокола канального уровня. Для Ethernet равен `1`.                  |
| **Protocol Type (PTYPE)**          | **Тип протокола**                | 16         | Тип сетевого протокола, для которого запрашивается адрес. Для IPv4 равен `0x0800`. |
| **Hardware Address Length (HLEN)** | **Длина аппаратного адреса**     | 8          | Размер физического адреса в байтах. Для Ethernet (MAC) равен `6` (48 бит).         |
| **Protocol Address Length (PLEN)** | **Длина адреса протокола**       | 8          | Размер логического адреса в байтах. Для IPv4 равен `4` (32 бита).                  |
| **Operation (OPER)**               | **Код операции**                 | 16         | Задает тип сообщения: `1` — ARP-запрос (Request), `2` — ARP-ответ (Reply).         |
| **Sender Hardware Address (SHA)**  | **Аппаратный адрес отправителя** | 48         | MAC-адрес устройства, которое отправляет данный пакет.                             |
| **Sender Protocol Address (SPA)**  | **Адрес протокола отправителя**  | 32         | IP-адрес устройства, которое отправляет данный пакет.                              |
| **Target Hardware Address (THA)**  | **Целевой аппаратный адрес**     | 48         | MAC-адрес получателя. В запросе не заполнен и состоит из нулей (`00...00`).        |
| **Target Protocol Address (TPA)**  | **Целевой адрес протокола**      | 32         | IP-адрес узла, чей физический MAC-адрес необходимо определить.                     |
